# 性能实测与踩坑记录

## 实测数据（Debian 13.7，内核 7.3.0-rc6）

| 项目 | 数值 | 备注 |
|---|---|---|
| eMMC 顺序读 | **44.9 MB/s** | 100 MB O_DIRECT |
| eMMC 顺序写 | **29.0 MB/s** | 64 MB + fdatasync |
| eMMC 4K 随机读 | 3.7 k IOPS / 15 MB/s | O_DIRECT |
| SD 卡顺序读 | **23.4 MB/s** | 4-bit / 50 MHz |
| 网络吞吐 | **93.5 Mbps** | HTTP 拉 116 MB 文件 |
| CPU 单核整数 | 163 Miter/s | 12 s 持续无降频 |
| AES-128-CBC | 25.4 MB/s | 纯软件 |
| SHA-256 | 34.4 MB/s | 纯软件 |
| 冷启动 | **14.5 s** | kernel 2.1 s + userland 12.4 s |
| 内存 | 970 MiB + zram 485 MiB | lzo-rle |

---

## 坑 1：eMMC 只有 2 MB/s

**现象**：顺序读写都在 2 MB/s 上下，大块写会把进程挂进 D 状态十几分钟。

**根因**：板级 DTS 的 `&emmc` 没有 `bus-width`。`mmc_of_parse()` 缺属性时按 1 bit 处理，
`mmc_validate_host_caps()` 随后打印 `drop UHS/DDR/HS200 support since 1-bit bus only`，
把 DDR/HS200 能力全部清掉。1-bit @ 50 MHz 理论上限 6.25 MB/s。

**修复**：补 `bus-width = <8>` + pinctrl（`dts/patches/0001`）。

---

## 坑 2：SD 槽同样只有 2 MB/s

**根因**：`&sd` 里既没有 `bus-width` 也没有 `cap-sd-highspeed`，按 1 bit / 25 MHz 默认速跑。

**修复**：`bus-width = <4>` + `cap-sd-highspeed` + `max-frequency = <50000000>`（`0002`）。

**注意**：SoC 的 SDIO0 时钟 mux 只有 15/50/75/100 MHz 四档，UHS-I 需要 1.8 V，做不到，
所以 50 MHz × 4 bit = 25 MB/s 就是天花板。

---

## 坑 3：开机 34 秒

**根因**：`boot-report-late.service` 里 `ExecStartPre=/bin/sleep 20`，而且它
`WantedBy=multi-user.target` + `After=multi-user.target`，被算进启动事务。
`multi-user.target` 11 秒就 reached 了，但 "Startup finished" 要等整个事务结束。

**修复**：把「延迟 20 秒后写报告」改成 timer（`OnBootSec=30s`），服务本身去掉 `[Install]`。
34 s → **14.5 s**。

---

## 坑 4：内核根本没编 zram

**现象**：装 `zram-tools` / `systemd-zram-generator` 都起不来。

**根因**：`.config` 里 `# CONFIG_ZRAM is not set`、`# CONFIG_ZSWAP is not set`，
`/sys/class/zram-control` 不存在。

**修复**：重编内核开 `CONFIG_ZRAM=y`（自动带 `ZSMALLOC`），配
`systemd-zram-generator` + `vm.swappiness=100` / `vm.page-cluster=0`。

> 重编时注意：`.config` 里 `CONFIG_KERNEL_LZMA=y` 会让 zImage 从 12.6 MB 缩到 9.1 MB，
> 这样才塞得进 12 MB 的 kernel 分区。

---

## 坑 5：TF 卡"读得好好的，一写就废"

**现象**：120 GB 卡读 18 MB/s 正常，写 9 MB 要 319 s，`blkid` 直接挂住。

**定位**（用 dd + md5 逐段验证，绕开文件系统）：

| 位置 | 写入 | 回读校验 |
|---|---|---|
| 0 MB | OK | ✅ |
| 2 GB / 20 GB / 60 GB / 100 GB / 112 GB | "成功" | ❌ **MISMATCH** |

更狠的一条：在 2 GB 处做「写前读 → 写 → 写后读」，三个 md5 **互不相同**，
回读内容是 `0xFF`（擦除态）——写操作返回成功，数据根本没落地，内核也不报 I/O error。

**结论**：NAND 磨损到 FTL 失效，属于介质报废。格式化救不回来。
同一台机器换一张好卡立刻 23.4 MB/s 且校验通过，排除槽子和驱动。

---

## 坑 6：内核不认 exFAT

`# CONFIG_EXFAT_FS is not set` 且 `# CONFIG_FUSE_FS is not set`，
装 `exfat-fuse` 也挂不上（没有 `/dev/fuse`）。

要读相机卡之类，要么重编内核开 `CONFIG_EXFAT_FS=y`，要么在别的机器上转存。

---

## 坑 7：假 MAC 导致网络时通时不通

dearjoe 镜像里的 `aa:bb:cc:00:51:20` 是伪造的，局域网里存在同 MAC 设备，
交换机会把帧转到错误端口 —— ping 大量丢包、SSH 握手超时。

修复：用本机唯一 MAC，写进 `/etc/systemd/network/10-eth0.network` 的 `[Link] MACAddress=`，
并关掉 DHCP（避免同时拿到两个地址）。

---

## 坑 8：100 Mbps 是硬件上限

`ethtool` 显示 PHY 支持 1000baseT，但：

- MAC 是 `hisilicon,hisi-femac-v2`（Fast Ethernet）
- DTS 里 `phy-mode = "mii"`，MII 物理上跑不了千兆

实测 93.5 Mbps（HTTP 拉大文件），已经贴着百兆线速。换交换机没用，换 SoC 才行。

---

## 其他值得记的

- **eMMC 写坏前兆**：进程长时间 D 状态 + `DTO timeout`，重启能恢复，但会复发
- **journald** 写在 eMMC 上，日志量大时建议 `Storage=volatile` 或转存
- **HDMI 输出**依赖 `histb-vo` / `histb-hdmi-1.4` 驱动，DTS 里 `&hdmi` `&vo` 必须 `okay`
